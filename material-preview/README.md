# 材质设计预览程序

零第三方依赖的材质设计预览系统：内置一套真实的 GLSL ES 3.00 子集编译管线
（预处理 → 词法 → 语法 → 语义 → JS 代码生成 → 动态模块链接），配合 CPU 软件
光栅化渲染，实现可切换法线贴图、透明模式与光照选项的材质预览。所有着色结果与
编译状态均由实际运算产生，不存在"只写选项状态、渲染永远走默认着色器"的捷径。

运行环境：Node.js >= 18（开发验证版本 v22.23.4），无需安装任何依赖、无需 GPU。

## 一、图形入口（主入口）

```bash
node src/cli.js serve
# 或 npm start
```

启动后在浏览器打开（以终端实际打印的端口为准，默认 8123）：

```
http://localhost:8123/
```

图形界面即着色器预览的主入口，全部预览、编译、诊断工作都在此完成：

- **场景流送视窗**：视口画面由服务端真实渲染后以 PNG 帧流送，帧头携带
  `x-variant-key`、`x-fallback`、`x-render-ms` 等实际编译/渲染状态；可切换
  球体 / 立方体 / 圆环三个自制模型并开启自动旋转。
- **结构选项（影响编译结构）**：法线贴图开关、透明模式（不透明 / Alpha 测试 /
  Alpha 混合）、光照模式（无光照 / Lambert / Blinn-Phong PBR）。每次切换都会
  触发真实的预处理与编译，界面明确显示"当前采用变体"与"等待编译变体"。
- **数值参数（仅更新 Uniform，不重编译）**：基础色、粗糙度、金属度、自发光、
  灯光强度、Alpha 截断值、法线强度。拖动滑块只更新 uniform，变体缓存数量不变。
- **编译卡片与变体缓存列表**：显示每次编译的耗时、缓存命中、变体身份 key 与
  目标状态（混合/深度写入）。
- **故障注入区**：可提交非法 GLSL，界面弹出编译诊断（阶段、行列号、消息），
  视口切换为醒目的品红棋盘格**替代材质**，旧管线不会伪装新效果已生效。
- **运行中着色器热换**：直接编辑当前材质的片元源码，点“保存文本（不更新画面）”
  只提交候选；“编译候选并热换”会在后台真实编译并检查资源绑定布局，通过后
  才一次性切换所有受影响材质实例，失败则保留上一份可运行版本并显示具体原因。
  面板同时显示已发布版本 / 候选版本、修订号、绑定布局哈希，以及
  “文本已改，画面未更新”这类如实状态，保存文本不会让界面假装效果已更新。
- **事件日志**：通过 SSE 实时展示编译、帧渲染、预热、热换、故障等事件。

## 二、命令行（仅作辅助）

```bash
# 渲染一帧到 PNG（辅助验证，主预览仍走图形界面）
node src/cli.js render --out frame.png [--material 材质ID]

# 固定操作序列基准：测量首次切换卡顿、新增变体数、缓存命中与复用
node src/cli.js bench

# 按已知场景需求、有限预算预热（可被取消，不枚举全部组合）
node src/cli.js prewarm --max-variants 4 --budget-ms 2000

# 故障注入：验证失败诊断与替代材质路径
node src/cli.js fault

# 辅助验证运行中热换：tint=成功采用 / broken=编译失败保留旧版本 / rebind=绑定布局改变
node src/cli.js hot-swap --body tint
```

命令行只作辅助；着色器预览、编辑、热换与回退的图形入口始终是 `serve` 打开的页面。

## 四、关键设计

### 结构选项与数值参数分离

- 结构选项（`NORMAL_MAP` / `BLEND_MODE` / `LIGHTING`）作为预处理宏参与
  `#if` 分支，改变实际参与编译的源代码，产生不同管线变体。
- 数值参数全部是 uniform，改动只写 uniform 缓冲，不触发任何编译。

### 缓存身份

变体 key 由编译器版本、管线类型、**预处理后顶点/片元源码哈希、顶点布局哈希、
目标状态哈希**共同构成：

```
v1|graphics|s<源哈希>|l<布局哈希>|t<目标状态哈希>|vs<顶点哈希>|fs<片元哈希>
```

结构不同的材质不可能命中同一缓存条目；非法结构值直接被拒绝（`INVALID_STRUCT`），
不会静默落到默认缓存。

### 编译失败与替代材质

预处理/解析/语义各阶段的错误都保留带行列号的 `CompileDiagnostic`，失败结果单独
缓存（不反复重试），同时挂载固定的品红棋盘格 fallback 变体并在渲染帧与界面上
显式标记 `isFallback`。

### 运行中热换与回退

热换不重启程序，而是按“候选 → 检查 → 原子发布”的流程在运行中替换管线：

1. **保存候选 ≠ 更新画面**：`POST /api/shader/candidate` 只提交源码（带单调
   递增的 `revision` 与 `editVersion`），返回 `editorTextSaved: true`；画面仍由
   已发布变体渲染。`POST /api/shader/compile` 编译并条件发布，
   `POST /api/shader/rollback` 回到已发布版本，`GET /api/shader` 读取当前程序状态。
2. **编译与绑定检查**：`compileSource` 走完整预处理/解析/语义/链接，并由
   `binding-layout.js` 根据两阶段真实声明的接口推出顶点属性、varying、
   uniform 与采样器绑定。未知 uniform、缺失采样器资源、varying 不匹配都会
   返回具体的 `bindingErrors`，候选不会发布。
3. **原子切换**：检查通过才把程序与所有绑定该程序的材质实例一起切到新变体，
   并依据新绑定布局准备兼容绑定组；旧绑定组不会交给不兼容的新管线。
4. **失败保留旧版本**：候选失败时 `published` 不变，`publishedKept: true`，
   `candidate` 记录阶段、行号与消息。
5. **晚返回结果不覆盖新代码**：每个任务带提交时的 `revision`，完成时若程序的
   `revision` 已前进，旧任务结果标记 `superseded` 并丢弃。
6. **延迟回收**：渲染帧对变体 `acquire`/`release` 引用计数；被替换的管线先进
   入 retired 表，最后一个使用者释放后才真正删除。
7. **定向失效**：发布新源码只清除该程序自己的旧源码条目；初版静态结构变体
   （`stage='graphics'`）继续有效，结构切换仍可命中。

界面在“着色器源码（运行中热换）”面板中对比已发布版本与候选版本，并单独显示
“文本已改，画面未更新”，避免把编辑文本保存成功误报成画面已更新。

### 有限可取消的预热

预热只接收"已知场景需要"的结构清单，受 `maxVariants` 与 `timeBudgetMs` 双重
预算约束，并支持 `cancelToken` 取消；不会在启动时枚举全部组合。

## 五、目录结构

```
src/shader/   GLSL 子集编译器：预处理、词法、语法、语义/代码生成、内置函数、值类型、材质模板
src/core/     变体身份 key、绑定布局分析、管线管理器（缓存/诊断/fallback/预热/延迟回收）、
              热换服务（候选/修订号/发布/回退）、预览场景服务
src/render/   程序化网格与纹理、CPU 软件光栅化、PNG 编码
src/server/   HTTP 服务：静态界面、控制 API、PNG 帧流送、SSE 事件
public/       图形界面（原生 HTML/CSS/JS）
tests/        零依赖串行测试运行器与用例（含 hot-swap.test.js）
```

## 六、界面操作路径（着色器热换用例）

1. `node src/cli.js serve`，浏览器打开终端打印的地址（默认 http://localhost:8123/）。
2. 左侧切换材质、右侧观察“编译状态”和变体缓存。
3. 中下“着色器源码（运行中热换）”面板：
   - 改一行颜色（例如把 `* 0.3 + vec3(...)` 的系数改掉），点 **保存文本**：
     “已发布版本”保持不动，“文本 vs 画面”显示“文本已改，画面未更新”。
   - 点 **编译候选并热换**：状态变为“已发布（与编辑器文本一致）”，视口画面
     真实变化，变体身份、绑定布局哈希、影响实例数同步更新。
   - 把 `void main()` 改成 `void main(` 再编译：候选被拒绝，面板给出
     `语法错误 (行:列)` 与阶段，视口仍是上一份可运行画面。
   - 声明一个引擎没有的 sampler（如 `uniform sampler2D u_missing;`）：候选被
     拒绝并列出 `MISSING_RESOURCE` 绑定错误。
   - 点 **回退到已发布**：不重编译，直接回到已发布版本。
