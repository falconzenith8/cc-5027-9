# 材质设计预览程序

零第三方依赖的材质设计预览系统：内置一套真实的 GLSL ES 3.00 子集编译管线
（预处理 → 词法 → 语法 → 语义 → JS 代码生成 → 动态模块链接），配合 CPU 软件
光栅化渲染，实现可切换法线贴图、透明模式与光照选项的材质预览。所有着色结果与
编译状态均由实际运算产生，不存在"只写选项状态、渲染永远走默认着色器"的捷径。

运行环境：Node.js >= 18（开发验证版本 v22.23.4），无需安装任何依赖、无需 GPU。

## 一、图形入口（主入口）

```bash
node src/cli.js serve
# 或 npm start
```

启动后在浏览器打开（以终端实际打印的端口为准，默认 8123）：

```
http://localhost:8123/
```

图形界面即着色器预览的主入口，全部预览、编译、诊断工作都在此完成：

- **场景流送视窗**：视口画面由服务端真实渲染后以 PNG 帧流送，帧头携带
  `x-variant-key`、`x-fallback`、`x-render-ms` 等实际编译/渲染状态；可切换
  球体 / 立方体 / 圆环三个自制模型并开启自动旋转。
- **结构选项（影响编译结构）**：法线贴图开关、透明模式（不透明 / Alpha 测试 /
  Alpha 混合）、光照模式（无光照 / Lambert / Blinn-Phong PBR）。每次切换都会
  触发真实的预处理与编译，界面明确显示"当前采用变体"与"等待编译变体"。
- **数值参数（仅更新 Uniform，不重编译）**：基础色、粗糙度、金属度、自发光、
  灯光强度、Alpha 截断值、法线强度。拖动滑块只更新 uniform，变体缓存数量不变。
- **编译卡片与变体缓存列表**：显示每次编译的耗时、缓存命中、变体身份 key 与
  目标状态（混合/深度写入）。
- **故障注入区**：可提交非法 GLSL，界面弹出编译诊断（阶段、行列号、消息），
  视口切换为醒目的品红棋盘格**替代材质**，旧管线不会伪装新效果已生效。
- **着色器源码热换面板（运行中替换）**：左栏编辑候选片元源码（草稿），右栏
  只读展示当前画面实际运行的已发布源码与编辑版本，二者可逐字比较。点击
  "编译并热换"后，候选先走过完整真实编译并做**资源绑定布局检查**，全部通过
  才切换受影响材质并刷新流送视窗；帧头新增 `x-source-id`、`x-source-edition`
  标明画面实际采用的源码版本。编译失败（语法/语义/预处理/绑定布局）时保留
  先前可运行版本并展示具体原因，"保存草稿"只存文本、不编译、不改画面。
- **事件日志**：通过 SSE 实时展示编译、帧渲染、预热、故障、热换发布/失败等事件。

## 二、命令行（仅作辅助）

```bash
# 渲染一帧到 PNG（辅助验证，主预览仍走图形界面）
node src/cli.js render --out frame.png [--material 材质ID]

# 固定操作序列基准：测量首次切换卡顿、新增变体数、缓存命中与复用
node src/cli.js bench

# 按已知场景需求、有限预算预热（可被取消，不枚举全部组合）
node src/cli.js prewarm --max-variants 4 --budget-ms 2000

# 故障注入：验证失败诊断与替代材质路径
node src/cli.js fault

# 着色器热换（辅助验证；主入口仍是图形界面的热换面板）
node src/cli.js hotswap --file candidate.glsl --out hotswap-frame.png
```

## 四、关键设计

### 结构选项与数值参数分离

- 结构选项（`NORMAL_MAP` / `BLEND_MODE` / `LIGHTING`）作为预处理宏参与
  `#if` 分支，改变实际参与编译的源代码，产生不同管线变体。
- 数值参数全部是 uniform，改动只写 uniform 缓冲，不触发任何编译。

### 缓存身份

变体 key 由编译器版本、管线类型、**预处理后顶点/片元源码哈希、顶点布局哈希、
目标状态哈希**共同构成：

```
v1|graphics|s<源哈希>|l<布局哈希>|t<目标状态哈希>|vs<顶点哈希>|fs<片元哈希>
```

结构不同的材质不可能命中同一缓存条目；非法结构值直接被拒绝（`INVALID_STRUCT`），
不会静默落到默认缓存。

### 编译失败与替代材质

预处理/解析/语义各阶段的错误都保留带行列号的 `CompileDiagnostic`，失败结果单独
缓存（不反复重试），同时挂载固定的品红棋盘格 fallback 变体并在渲染帧与界面上
显式标记 `isFallback`。

### 有限可取消的预热

预热只接收"已知场景需要"的结构清单，受 `maxVariants` 与 `timeBudgetMs` 双重
预算约束，并支持 `cancelToken` 取消；不会在启动时枚举全部组合。

### 着色器源码运行中热换与回退

热换不重启程序、不重置场景，在同一预览运行时内完成管线替换，关键约束：

- **候选先验证、后切换**：候选片元源码先经过预处理→词法→语法→语义→代码生成，
  再做**资源绑定布局检查**（`src/core/bindings.js`）。任何阶段失败都返回带阶段
  与行列号的诊断，在用管线与已发布源码完全不动；视口继续显示先前可运行版本。
- **绑定布局改变时准备对应材料**：新管线声明的采样器必须是运行时能提供纹理的
  槽位（`u_baseColorTex / u_normalTex / u_occlusionTex`），否则在切换前被
  `BindingLayoutError` 拒绝；新增材质 uniform 补类型化默认值。绑定组按新管线
  布局重新准备，旧绑定组绝不会交给不兼容的新管线。
- **编辑版本门控**：每次提交携带单调递增的 `sourceEdition`，编译任务把版本
  带进链接阶段。连续保存后晚返回的旧结果即使成功也判为 `stale` 丢弃，绝不
  覆盖更新的代码；只有最新提交能发布。
- **延迟回收**：源码更新只按 `sourceId` 失效**相关**缓存条目，其他材质的静态
  变体缓存继续有效。仍被在用材质引用的旧管线进入 `retired` 而非立即释放，
  待该材质切换到新管线、确认无引用后才真正回收；进行中的链接任务计入
  `inFlightCompiles`，任务未决前其模块不会被回收。
- **候选与已发布可比较**：材质分别保存 `shaderDraft`（草稿）与
  `publishedShader`（已发布），界面双栏对照并明确 `viewportInSync`。
  文本保存成功仅更新草稿，只有编译发布后流送视窗才会变化，帧头的
  `x-source-id / x-source-edition` 是画面实际采用版本的权威凭据。
- **回退走真实重编译**：回退模板着色器同样经过编译路径，并复用模板静态变体
  缓存（同身份命中），不通过重启程序回避生命周期问题。

热换用例（`tests/hotswap.test.js`、`tests/hotswap-http.test.js`）覆盖：
绑定字段改变与未知采样器拒绝、语法/语义/预处理失败保留旧版本、连续保存的版本
门控、场景切换期间编译完成的版本采用、相关条目失效与静态缓存保留、在用管线
延迟回收与释放、失败后修正恢复、模板回退，以及图形界面所调用 HTTP 接口的
端到端帧头与编译状态核对。

## 五、目录结构

```
src/shader/   GLSL 子集编译器：预处理、词法、语法、语义/代码生成、内置函数、值类型、材质模板
src/core/     变体身份 key、管线管理器（缓存/诊断/fallback/预热/热换/延迟回收）、
              资源绑定布局（bindings）、预览场景服务
src/render/   程序化网格与纹理、CPU 软件光栅化、PNG 编码
src/server/   HTTP 服务：静态界面、控制 API、PNG 帧流送、SSE 事件
public/       图形界面（原生 HTML/CSS/JS），含着色器源码热换面板
tests/        零依赖串行测试运行器与用例（含热换与热换 HTTP 用例）
```
